# 定时筛选与手机查看

用户使用流程：交易日到点自动筛选 → 收到“观澜筛选完成，点击查看” → 打开观澜实时页查看结果。手机不参与计算，也无需保持 App 打开。

默认北京时间 14:30、14:45、14:50 执行；09:10 静默准备历史特征。Mac 优先，Mac 实时心跳失联45秒或运行租约失效后，由服务器在有效窗口内接管。与手动全历史重算的队列分开。暂停自动策略仍可手动检查。

2026-09-07 已修复 ProMax 备用通配符与缺失时间字段兼容：明确代码分批，必要时改取新浪带源时间的完整报价；两源都不满足新鲜度时仍暂停本轮。App 会显示来源与具体失败阶段，见 [备用兼容与验证](REALTIME_FALLBACK.md)。

## Bark 配置

1. iPhone 安装并打开 Bark，允许通知。
2. 复制首页的测试 URL，通常是 `https://api.day.app/设备密钥/测试内容`。
3. 观澜 → 实时 → 右上设置，粘贴至 Bark 地址并保存。
4. 点击“发送测试通知”，在 Bark 收到后点击，应打开观澜实时页。也可在 Mac 的“实时提醒 → 提醒设置”操作。

只向固定官方 `https://api.day.app/push` 发送 HTTPS POST。地址里的设备密钥存入服务器私密设置，请勿写 Git。免费个人 Apple ID 签名没有原生 APNs 权限，因此手机系统通知显示发送 App 为 Bark，点击后打开观澜。App 内有每次执行和通知记录。`Bark 已接受` 只代表接口接受请求；网络超时记为“发送结果待确认”，不会盲目重发造成重复提醒。

## DeepSeek（可选）

同一设置页填写自己的 API Key 后开启。默认关闭。只发送候选的公开代码、量价条件和待核验项；固定官方 API，可选 V4 Flash / V4 Pro。每轮输出最多600 tokens、请求20秒超时，不执行模型生成的代码，也不允许修改规则入选列表。AI 不可用不影响选股或完成通知。配置密钥前不产生真实模型调用。

## 运维

Mac 节点安装或重启：

```
cd /Users/bennie/quanta/ashare-mac
bash scripts/install_realtime_worker.sh
```

节点使用 `settings/mobile-worker.json`；Mac 设置页使用权限更高但独立的 `settings/mobile-viewer.json`。安装脚本可从同机 `ashare-ios/settings/手机连接.guanlan` 安全初始化 viewer。文件均应为600权限，并被 Git 忽略。

服务器代码位于 `/opt/guanlan-app`，在复制代码后运行：

```
bash /opt/guanlan-app/deployment/setup_realtime.sh
systemctl status guanlan-realtime.service
```

不新增公网端口，复用原来 HTTPS 443 和配对验证。服务仍是 `guanlan-worker` 非 root 运行，独立内存上限600M。结果和设置在 `/srv/guanlan-mobile/jobs/realtime`；历史特征/补充数据在 `/srv/guanlan-mobile/realtime-cache`，不覆盖收盘仓库。
