# 9月14日行情缺失排查与恢复

## 故障原因

9月14日14:30、14:45、14:50三轮实时任务均由 Mac 领取，归档为 `data_incomplete`，提示达塔数据端未连接。当晚检查时，Mac 后台节点与服务器均在线，已发布数据仍停留在9月11日。按已有调度约定，Mac 心跳在线时服务器不会另起一套计算。

恢复达塔客户端并用已有私有登录配置重新登录后，D6日线接口恢复。账号授权仍有效，本次未购买、充值、重置凭据或在服务器登录达塔。

收盘更新还遇到 ProMax 的多种响应：全量股票名录/因子超出返回行数预算，旧20000行请求被拒绝，部分分页在5000行请求下失败，另有429及503。名录的部分切片还包含同代码的不同名称、行业或字段版本，不能按第一条随意合并。

## 修复

- 普通查询每页5000；明确行数超限时在同一offset降为1000，继续检查跨页重复及截断。
- 复权因子仅按该日实际日线代码取数，每批100代码、请求上限1000；原始返回满页时拒绝，不能依靠去重掩盖截断。
- 同一进程各ProMax实例共享2.1秒请求间隔；有效Retry-After在60秒以内完整遵守，要求更久时停止本轮，保留原结果。
- 因子单日查询最终返回HTTP503时，可对相同代码改用同日start_date/end_date再查一次。401、普通400、429及超过等待预算不会换查询形式。两种形式都失败时仍拒绝整批。
- 所有分批均验证代码、日期及冲突。因子缺数仍由100%日线覆盖检查拒绝，没有填1、沿用旧因子或把错误计成零收益。
- 名录不可用但已有验证过的股票集合时，允许独立获取这些股票的价格；名称和行业沿用上一有效名录，并在报告记录失败和提示。原有日报逻辑因此暂停行业排序，避免把未更新的行业信息写成当日结论。

接口参数参考 [Tushare股票基础信息](https://tushare.pro/document/2?doc_id=25) 与 [复权因子](https://tushare.pro/document/2?doc_id=28)；ProMax实际请求上限、分页及错误行为另以本次现场响应和回归测试确认。
