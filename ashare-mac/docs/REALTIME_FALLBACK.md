# 实时报价备用兼容修复

2026-09-07 14:30 的失败由 ProMax 的备用路由暴露：`rt_k` 返回“wildcards need CityData”，不接受 `0*.SZ` 等通配符。另外，原字段投影遗漏 `updated_at`；显式代码的部分备用响应连交易日期/时分秒也没有。不能给这些价格填上本机请求时间。

## 当前取数约定

1. 每批最多 200 个明确的沪深代码，最多 3 个并发请求，ProMax 仍为主源。股票和沪深300都显式保留 `trade_time` 与 `updated_at`。
2. 每条主源报价先核验代码、OHLC、量额单位和源时间。源时间有效的整条报价保留；缺失或过期的股票改取新浪 HTTPS 源站的完整报价，包括价格、量额、交易日期和时分秒。两个来源不拼接同一股票的字段。
3. 当主源某批超过 10% 无法使用时，本轮后续批次直接走备用，避免不断等待同一种错误；下一轮仍先尝试 ProMax。已经在途的主源请求也必须通过相同校验。
4. 新浪连接固定为 `https://hq.sinajs.cn/list=...`，只发送公开股票代码；不接收或传递 ProMax Key，禁止重定向，单次限制 6 秒和 2 MiB。股票数与代码格式在网络请求前校验。源站字段中的日期和时钟必须真实存在，不从 HTTP Date、请求时刻或其他股票借用。
5. 行情最多允许 180 秒时差，并核对当日日期；未来超过 15 秒的报价也拒绝。主备都无有效时间时，股票不会进入候选；全池覆盖不足 90% 或沪深300缺少有效报价时停止本轮。
6. 分钟查询最多 3 个并发；失败保留七步法的“待分时核验”。全部网络请求后再核验一次股票和指数新鲜度。

同一份结果可以包含不同股票来自不同源，但每只股票始终使用一份完整、有效的原始记录。App 原有警告区域显示 ProMax/新浪有效报价数量及指数来源。当前手机版本即可读取这些信息，无需修改配对或 Key。

## 失败记录

结果新增可选 `failure_stage`、`failure_code`、`quote_diagnostics` 和 `index_diagnostics`，继续使用原有授权、租约和发布接口。已安装 App 忽略不认识的扩展字段，并显示具体阶段的中文失败消息。

Mac 的 `.cache/realtime-worker/diagnostics/` 与服务器的 `/srv/guanlan-mobile/realtime-cache/diagnostics/` 保存最近 30 个任务的阶段记录。文件名从任务 ID 哈希生成，内容包含阶段、耗时、结果状态及异常类型；不保存租约、凭据、异常原文或供应商响应。诊断文件写入失败不影响有效计算。子进程失败、超时或崩溃仍通过原租约提交空候选的失败记录；迟到或失去租约的任务不能覆盖结果。

运行检查还发现，日线任务完成后 Mac 没有留下已构建的数据镜像，下一次实时任务会重复下载约 54 MiB 文件并触发同步时限。现在 Mac 会预缓存自己的已校验构建数据，但只有后续服务器版本确认才能切换镜像指针；实时任务已有覆盖前一交易日的完整本地镜像时直接使用。必须下载时采取可清理子进程的有界等待。

## 验证与维护

- 回归覆盖：明确分批、更新时间保留、缺时整行替换、过期/未来时间拒绝、未请求代码过滤、完整 4001 股测试池筛选与租约发布、通知去重、分钟失败以及诊断不泄漏凭据。
- 当晚真实 ProMax 指数响应已包含 `updated_at`；新浪返回的股票与指数包含源日期及时分秒。收盘后的旧报价仍被当晚新鲜度校验拒绝，不用于生成实时候选。盘中结果需在下一交易时段进一步实测。
- 修改位于 Python 引擎与后台节点，盘后策略、日线仓库和个人配对不受影响。保持每日总结与实时设置的原有开关。
- 更新前等待盘中租约和普通数据队列空闲，备份服务端代码，再同时更新 `engine/` 与 `mobile_server/`；恢复三个服务器服务及 Mac 后台节点。若回滚，先停新任务再恢复代码备份，保留已有报告与私密配置。

核验依据为当日实际 ProMax 响应、[新浪报价源站](https://hq.sinajs.cn/list=sh000300)及本项目自动化测试；不假设供应商备用路由具备主源的字段或查询能力。
