# 行情服务器部署

## 目标与接口约定

用户授权部署到 106.14.125.189。服务器运行 Ubuntu 22.04、Python 3.10，约 1.6 GB 内存、35 GB 可用磁盘。本次默认将行情集中保存，Mac 通过只读 SSH 接口同步后执行选股；不在小内存服务器上运行全市场 pandas 计算。

数据仅包含选股依赖的五张公开行情/参考表：daily、adj_factor、stk_limit、stock_basic、trade_cal。合并原始数据与新工程补充数据，校验后生成不可变版本。不会复制账户持仓、研究账本或任何密码/API 密钥。

版本格式为 `YYYYMMDD-<16 hex>`，内容清单 `manifest.json` 含 schema_version、revision、as_of、每张表的行数、字节数与 SHA-256。服务器以 `current` 符号链接指向已校验发布的版本。

SSH 接口仅允许：

- `manifest`：读取当前版本的 JSON 清单。
- `file <revision> <filename>`：读取该不可变版本中允许的五张 Parquet 文件。

数据账户 `guanlan-data` 使用独立密钥；authorized_keys 强制运行固定网关，并限制交互终端、端口转发、代理转发及任意命令。数据和程序由 root 持有，数据账户只有读取权限。Mac 不保存 root 密码。无需开放额外公网端口。

Mac 校验清单、大小、SHA-256 和 Parquet 行数，全部通过后原子切换缓存版本。失败保留旧缓存。切换“服务器 / 本地”数据源时，服务器模式使用独立空补充目录，避免与本地 ProMax 补充数据混合。

## 目录

- 服务器程序：`/opt/guanlan-data/`
- 服务器数据：`/srv/guanlan-data/releases/<revision>/raw/`
- 当前数据：`/srv/guanlan-data/current`
- Mac 公共连接配置：`settings/server.json`（忽略 Git）
- Mac 缓存：`.cache/server-data/current`
- Mac 只读账户私钥：`~/.ssh/guanlan-data-106.14.125.189`，权限 600；不进入工程、服务器或 Git。

## 实现与验收

1. 本地生成五表数据包和清单，日期、主键、跨表覆盖与读回校验通过。
2. 上传版本至独立 staging 目录；远端逐文件校验 SHA-256，再原子发布。
3. 数据账户可读取 manifest 和白名单文件；任意命令、路径穿越、符号链接逃逸均拒绝。
4. Mac 下载后逐文件校验，使用原有选股引擎完成一次真实分析。
5. 保留本地模式及已有数据；记录部署、回滚与后续发布命令。

本次不新增定时任务。服务器端数据的后续发布使用管理员 SSH；Mac 的“同步服务器”读取服务器已发布版本。ProMax 本地更新功能仍在本地模式提供。

```sh
cd /Users/bennie/quanta/ashare-mac

# 只下载服务器已发布的版本，等价于应用“同步服务器”的同步步骤。

```

发布脚本使用管理员 SSH 认证提示，不保存密码。临时 SSH 复用连接在脚本退出时关闭。它只上传五表行情包，不上传本机配置、策略、账本或密钥。`--refresh` 更新阶段失败时脚本停止；日期缺口会留在本地更新报告，应按实际发布清单日期判断新鲜度。

### 版本保留与回滚

每次成功打包、发布和同步后，分别清理本机打包目录、服务器 releases 和 Mac 缓存 releases。长期保留当前及最近两个历史版本；其他版本从退出 current 起至少保留 24 小时，避免在传输中被移除。旧版本第一次被纳入清理时也有 24 小时宽限。因此短时间内可能超过三个版本。只删除格式及清单校验通过的自有版本目录，未知目录和符号链接保持原样。服务器与 Mac 不需要定时清理任务。

服务器管理员可查看现存版本后回滚。将下面的版本号替换为服务器实际保留的版本；发布器会重新验证五表大小与 SHA-256，然后原子切换 `current`：

```sh
ssh root@106.14.125.189 'ls /srv/guanlan-data/releases'
ssh root@106.14.125.189 'python3 /opt/guanlan-data/publish.py --root /srv/guanlan-data --revision 20260904-c0eccf474694bb2b'
```

Mac 再点击“同步服务器”即可采用回滚版本。暂时离线时可继续用已经验证的缓存“重新选股”；同步失败不会替换缓存或报告。没有旧缓存的首次安装必须先成功同步一次。

### 传输与容量限制

清单上限 64 KiB，单文件上限 512 MiB，单版本上限 1 GiB。客户端流式传输时即时限制响应大小，超出清单声明即终止；单次 SSH 操作最多 300 秒。错误输出丢弃而不收集服务端详细信息，避免无限积累或泄露环境信息。数据量超过当前协议限制时，需要先评估分区方案再扩容。
