## 交付行为

1. 日线完整日期按上海交易日历和 15:10 收盘数据可用时点计算。盘前、盘中使用上一完整交易日；日历不足显示未知，不能误报过期。实时区分等待时段、已完成无候选、数据不足、休市；手动时段外检查不替换最近一次完整筛选。
2. 默认工作台从同一发布清单读取四策略，Mac 继续作为后台优先计算节点。切换读取已校验缓存，后台预取同版本其余策略；只在用户更新/重算时提交统一任务。保留独立本地研究入口。搜索统一为全股票池；自选通过逐条操作同步，并支持离线待提交和旧本机列表合并导入。
3. 每个筛选轮次独立保存。新通知携带对应轮次，点击旧通知也能看到其原消息。缺少旧明细明确提示，不用最新结果代替。界面可选历史轮次，并查看初筛/复核/最终检查；数据失败与 0 候选分开。
4. 首页优先显示最新候选、昨日结算、下次检查；股票池统计收起。K 线标出本次入选/观察日及参考位置、失效参考。总结增加可核验的跨日市场变化、名单新增/保留/移出与失效条件，让 AI 解释变化，减少重复数字。

## 增量接口

现有认证、固定证书、响应上限、错误结构保持。新响应字段为可选，旧客户端仍可读取。

- `GET /v1/status` 增加 `market_status`：`expected_as_of`、`phase`、`checked_at`、`calendar_covered`。phase 为 `before_open` / `trading` / `after_close` / `closed` / `unknown`。客户端将自己的报告日期与最新完整日期比较，离线时明确标明缓存。
- `GET /v1/watchlist`：`schema_version=1, revision, updated_at, codes`。代码唯一、排序、最多 1,000 条。
- `POST /v1/watchlist`：`operation_id` 为 UUID，`ts_code` 为有效代码，`action=add|remove`。逐条操作幂等，相同 ID 不同内容拒绝。返回当前完整状态。客户端持久保存未确认操作；首次合并原有本机自选，不提交全量覆盖。
- `GET /v1/realtime/history`：最近 90 个筛选或复核轮次摘要；每项包含 slot、date、generated_at、kind、status、message、executor、两策略数量。手动时段外准备不作为完整筛选。
- `GET /v1/realtime/runs/{slot}`：固定轮次的完整报告。slot 只允许原交易日轮次格式与 `manual-UUID`。
- `GET /v1/realtime/events/{uuid}`：`event, report, message`。report 可为空；旧提醒无法绑定时保留原消息和明确原因。
- 本机报告缓存保留当前完整四策略、上一代及原动量缓存；服务器实时明细最多 1,000 轮、通知原文最多 3,000 条。较旧明细到达保留上限后，仍在归档的通知保留原文并标明明细不可用，不改绑新结果。
- 实时报告增加可选 `run_state=waiting|complete|data_incomplete|closed`。保留原 status 兼容性。新通知增加 `run_id`；每日总结的日期链接继续有效。
- 每日 evidence 增加可选 `market_changes` 与 `selection_changes`，所有比较来自已校验的历史数据/精选；缺失时为空。AI 不计算策略收益，不推断未经核查的资金、公告或财务因果。
