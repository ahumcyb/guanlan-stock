# 每日收盘总结

用户要求每天收盘后根据当日行情自动生成总结，使用提供的 DeepSeek API Key，并能在 App 更换 Key。行情与四策略计算沿用 Mac 优先、失联后服务器接管；DeepSeek 仅由服务器调用，密钥复用受保护的实时服务配置，不交给 Mac worker。

## 流程与日期契约

1. 上海时区，已确认开市的交易日 16:10 起启动；重启或周末首次启用时可补最近一个已到该时点的交易日。交易日历不覆盖当前日期时等待更新。
2. 为普通单任务队列提交 `refresh`，内部携带 `purpose=daily_review` 和 `expected_as_of=YYYYMMDD`。用户正在执行的任务优先完成，不覆盖、不并发。Mac 与备用服务器都传递该日期到构建器。
3. 数据更新显式指定日期，并强制重新请求该日 daily、adj_factor、stk_limit。记录收盘后抓取时刻、规范化切片哈希与行数。即使之前已有完整盘中分区，也不能跳过。
4. 构建和上传发布均验证目标日期、当日三表证明、完整四策略 generation/data_revision。日期错误、三表更新失败或证明与打包内容不一致时保留旧版本，不调用 AI，不发送成功提醒。股票名称/行业更新问题保留为元数据警告。
5. 从已发布的固定版本计算市场涨跌、成交额、涨跌停、行业分布及四策略候选摘要，并按下述“昨日精选”口径结算策略观察涨跌，保存证据哈希。数值由程序生成，DeepSeek 只解释这些量价事实，不代替新闻核验或改变候选。
6. 每日状态与成品持久保存，自动失败每 20 分钟重试、次数有上限。发布已经完成时直接续跑总结。AI 发送前落盘；重启遇到不确定的已发请求不自动重复收费，保留数字总结并允许手动重试。
7. 成品保存后加入 Bark outbox，同一日期的成功提醒、失败提醒分别去重；失败后手动恢复可能各收到一次。发送结果不明不重复推送。点击进入新版观澜的收盘总结。AI 不可用时保留定量摘要，单独显示原因。

## App 与 API

- `GET /v1/daily`：公开设置、当前状态、最近成品和最多 30 条历史索引；不返回 Key。
- `GET /v1/daily/YYYYMMDD`：该交易日成品，日期严格校验、返回体有上限。
- `POST /v1/daily/settings`：自动总结、通知、模型与 Key 设置，复用既有认证和原子私有配置。空 Key 保留原值，明确清除才移除。
- `POST /v1/daily/generate`：补生成最近应完成的收盘日；`retry_ai=true` 只重做 AI，`refresh_facts=true` 从固定发布凭证重新核验事实与昨日精选结算，然后重做解读。同日期成功提醒仍去重。

Mac 新增收盘总结页面；iPhone 在首页提供入口并支持通知直达，不增加第六个底部标签。两端能查看日期、量价事实、四策略摘要、DeepSeek 解读和历史日期，并有 SecureField 更换 Key。新字段保持可选/兼容原三、四策略客户端。

新环境默认模型沿用 `deepseek-v4-flash`，保留 V4 Pro 选项；当前服务器已选用通过实测的 `deepseek-v4-pro`。固定官方 HTTPS 地址、禁止重定向、限制输出与超时、解析严格 JSON，不执行模型文本。实际调用费用由用户 DeepSeek 账户承担。

模型输入明确标注只有单日横截面，没有历史成交额、指数、资金流或估值数据。针对实测出现的无依据推断，增加有限的语义范围检查：资金流向、估值高低、指数点位以及回顾正文的放量/缩量等跨日结论会回退到定量摘要。准确策略名称和明确的未来条件观察可以保留。这不是通用事实审查，AI 文字仍需结合独立事实卡片判断。

涨跌家数比由程序预先计算。MA20 上方池宽使用独立、明确的百分比字段传给模型，不能与涨跌家数比混用；标题直接由行业排序生成。这些派生输入不改变原始证据及其哈希。

## 昨日精选、今日结算

上一交易日由 SSE 交易日历确定（周一对应上周五）。只读取当时已经保存并能验证可用时间的精选，绝不用今天入选股票的今天涨幅解释策略收益。

每只股票观察涨跌 = `今日收盘 × 今日复权因子 / (昨日收盘 × 昨日复权因子) − 1`。同时核对历史行情收盘价与保存精选的价格一致；缺行情、缺因子或不一致均为未结算，不按 0 处理。仅当全部精选可结算才显示策略等权均值；无精选显示无样本。它是收盘到收盘的观察表现，未计实际仓位、买卖成交或费用，不是可执行交易净收益。

精选不可变保存于 `jobs/daily/selections/日期/版本.json`，内含来源 generation、data_revision 和 SHA-256。迁移旧版本时优先验证收盘发布凭证；没有凭证只允许评价日之前已生成的旧报告。评价日临时重算的旧日期结果不冒充昨日已知信号。更换策略时保留原策略名称，例如 9 月 7 日结算原动量精选，新左侧策略没有此前样本。

模型只收到昨日精选的结算明细，以及今天各策略新选数量；今天新选股票的今天涨幅不进入策略收益输入。App 分别展示“昨日精选 · 今日结算”和“本日新选 · 留待下一交易日评价”。旧成品没有结算字段时提示重新核验，并隐藏旧的策略收益解读。

## 验证重点

16:10 不回退昨日；盘中完整分区必须重抓；partial 三表失败不发布；Mac/服务器传递相同 expected 日期；发布元数据不能伪造证明；重启不重复收费/提醒；无新闻不编造原因；Key 不进入报告、URL、日志或 Git；旧客户端可继续读取原策略。

接口依据：[DeepSeek 官方接口](https://api-docs.deepseek.com/)、[JSON Output 约束](https://api-docs.deepseek.com/guides/json_mode/)。

## 运行与升级

- Mac 1.6.0（7）：左侧「收盘总结」或首页入口 →「总结设置」可修改 API Key。iOS 1.5.0（7）：首页「收盘总结」→ 右上角「设置」。空白 Key 保留服务器上的原值，两端设置同步。
- 自动总结独立于盘中选股、盘中 AI 的开关。调度在服务器已有 `guanlan-realtime` 服务运行，App 关闭也不影响；Mac 计算节点仍由登录后的 LaunchAgent 运行。
- 成品位于服务器 `jobs/daily/reports/YYYYMMDD.json`，状态与独立心跳位于 `jobs/daily/`，收盘发布凭证位于 `jobs/closing-receipts/`。重启服务可继续未完成任务，成品和 Key 不放在代码目录。
- 发布时先保持自动总结关闭，等待现有数据与盘中任务空闲，暂停 Mac 两个后台节点，备份并更新服务端 Python 代码，重启 API、数据调度、实时调度三个服务，再启动 Mac 节点。验证心跳、API 与客户端后再开启自动总结。
- 回滚先通过设置关闭自动总结，等当前数据任务完成后备份 `jobs/status.json`。若恢复不支持每日总结的旧代码，须从已结束任务的状态中移除 `purpose` 与 `expected_as_of` 两个新字段，再恢复代码并重启三个服务与 Mac 节点；活动任务不可这样处理。保留原状态备份、数据版本、总结成品和私密配置，旧 App 可继续读取原来的四套策略。
- Bark 通知可在手机离开 Mac 时接收。新版页面需要先更新手机 App；已经配对的设备重新连接同一 Wi-Fi 后通常可无线安装，连接不可用时保留签名安装包。
